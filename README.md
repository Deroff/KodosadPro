# Задание 6 — Кодосад Studio

Нативное WPF-приложение для исследования алгоритмов сжатия без потерь. Решение открывается файлом `KodosadStudio.sln` в Visual Studio 2022.

Функции: Хаффман, Шеннон–Фано, RLE, обратное декодирование, сравнение методов, энтропия и избыточность, дерево и таблица кодов, журнал шагов, открытие текстовых файлов, защищённый файл проекта KODO, экспорт TXT/CSV, переносимый бинарный архив Хаффмана `.khf` и персональный архив расчётов. Внутри KHF коды и битовый поток упакованы в двоичный формат; таблица символов нужна для восстановления без исходной сессии, а SHA-256 обнаруживает повреждение файла. Декодер ограничивает восстановленный результат десятью миллионами символов для всех трёх алгоритмов и сразу отклоняет небинарный вход для двоичных кодов. В архиве расчётов хранятся исходный текст именно того запуска, результат и метрики, поэтому последующие изменения черновика не подменяют прошлые результаты. Автосохранение пишет снимки по очереди, повторяет временно неудачную запись и повторно ставит в очередь правки, внесённые во время предыдущего сохранения. Добавлены регистрация и вход, уникальные логин/почта, усиленная проверка пароля, блокировка входа после пяти неудачных попыток и автоматическое сохранение персональных проектов/результатов в SQL Server.

Тексты проектов, сохранённые снимки и выходные потоки шифруются средствами DPAPI для текущего профиля Windows. Формат проекта KODO — версионированная JSON-оболочка с зашифрованной полезной нагрузкой; повреждённый/подменённый файл отклоняется. Пароли не хранятся в открытом виде: используется PBKDF2-SHA256 с индивидуальной солью. RLE-декодер проверяет входные серии и ограничивает размер результата. Схема БД находится в `KodosadStudio/Database/001_core.sql`: переходы версий 1→2→3 выполняются повторяемыми миграциями без пересоздания таблиц. v3 добавляет состояние подтверждения почты и таблицы одноразовых кодов со сроком, лимитом попыток, FK и CHECK. База `KodosadStudioDb` работает на `(localdb)\MSSQLLocalDB`; актуальный pipe приложение получает автоматически. Для другого экземпляра задайте `KODOSAD_SQL_SERVER`, для отдельной базы — `KODOSAD_DATABASE_NAME` (латинские буквы, цифры и `_`).

Регистрация требует подтверждения почты: приложение запрашивает шестизначный код через общий Mail API, принимает его 10 минут и ограничивает проверку пятью попытками. Для восстановления пароля на экране входа запрашивается отдельный 128-битный одноразовый код; в SQL хранится только его SHA-256, срок 10 минут, не более пяти ошибок и минутный интервал между запросами. Сброс доступен только для подтверждённой почты. Учётные записи, созданные до v3, намеренно остаются неподтверждёнными: их владелец должен войти со старым паролем, открыть профиль, повторно ввести текущий пароль и подтвердить **уже сохранённый** адрес кодом из письма. Привязки произвольного нового адреса этот сценарий не даёт. Если старый пароль или сохранённый почтовый ящик недоступен, самосброс невозможен; нужна проверенная административная процедура, не автоматическое присвоение нового адреса.

HTTPS-адрес и Bearer-токен задаются в окне входа/регистрации; приложение автоматически подхватывает совместимые DPAPI-настройки из RouteStudio и сохраняет локальное переопределение зашифрованным для текущего пользователя Windows. Также поддерживаются `KODOSAD_MAIL_API_URL` / `KODOSAD_MAIL_API_TOKEN`. Для совместимости с прежним локальным API предусмотрены отдельные fallback-маршруты регистрации и сброса; код сброса никогда не отправляется через маршрут регистрации. SMTP-секрет хранится только на сервере Mail API. Отправка письма зависит от запущенного RouteStudio Mail API, его токена и SMTP-настроек; приложение не гарантирует доставку само по себе.

Дизайн построен по логике аналитических рабочих сред CyberChef и JetBrains: источник и операция слева, метрики и результат в центре, инспектор алгоритма справа. Визуальный стиль самостоятельный.

Решение для Visual Studio: `KodosadStudio.sln` (приложение, модульные, SQL-интеграционные и визуальные тесты). Актуальная сборка с исправленным подключением: `outputs/CourseworkBuilds/06-KodosadStudio-SqlServer-2026-10-02-LocalDbFix/KodosadStudio.exe`. Запускайте EXE из папки сборки; .NET включён, SQL Server LocalDB требуется отдельно. Программа получает актуальный именованный канал экземпляра через `SqlLocalDB.exe`, поэтому подключение переживает автоматический перезапуск LocalDB. SQL-интеграционные тесты используют случайную временную базу и удаляют только её; пользовательская `KodosadStudioDb` не затрагивается. Для регистрации, подтверждения старой почты и сброса нужен доступный Mail API с настроенной отправкой писем. Проверенная copy-only копия БД после миграции v3: `outputs/CourseworkApps/06-KodosadPro/database-backups/KodosadStudioDb_v3_2026-10-02_095402UTC.bak`; копия перед миграцией сохранена рядом.

При запуске окна входа приложение временно использует `OnExplicitShutdown`, затем переключается на закрытие вместе с главным окном после успешной авторизации. Это предотвращает завершение процесса в промежутке между закрытием окна входа/регистрации и показом рабочего пространства.

Для воспроизводимых снимков экранов используйте отдельные команды `KodosadStudio.Tests --capture-auth`, `--capture-register`, `--capture-profile`, `--capture-reset`, `--capture-email-verification`, `--capture` и `--capture-history`; захват не вводит учётные данные и не меняет пользовательскую базу. Экраны сброса и подтверждения v3 находятся в `outputs/qa/kodosad-reset-v3/`, старые изображения выпуска r9 — в `outputs/qa/kodosad-r9/`.
